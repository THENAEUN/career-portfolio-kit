# 기본 구성: 회사·프로젝트별 성과 챕터

기본 포트폴리오는 `표지 → 성과 Summary → 일하는 방식(선택) → 회사·프로젝트별 간지와 성과 상세 → 수상·학력·역량 → 채용 가치 요약`으로 구성한다. 대표 프로젝트 하나의 문제·방법·실험만 8쪽으로 풀어내는 구성을 모든 지원자의 기본으로 삼지 않는다.

## 전체 흐름

| 구간 | 보여줄 내용 |
|---|---|
| 표지 | 이름·지원 직무·근거 있는 포지셔닝 한 문장 |
| Summary | JD와 관련된 대표 성과 3~4개. 성과·기여 범위를 크게, 회사·역할을 짧은 보조 정보로 배치 |
| 일하는 방식, 선택 | 실제 사례가 뒷받침하는 문제 정의·실행·성과 연결 방식 |
| 회사·프로젝트 간지 | 회사 또는 프로젝트 그룹 이름·역할·기간·제품/업무 영역과 해당 챕터의 핵심 성과 목록 |
| 성과 상세 | 한 장에 핵심 성과·의사결정 하나, 실제 근거·본인 기여·결과·조건을 연결 |
| 수상·외부 인정, 해당 시 | 공식 수상명·연도·주최·관련 작업과 실제 사진/공개 근거 |
| 학력·자격·역량, 해당 시 | 직무에 관련된 학력·연구·자격·도구의 실제 활용 범위 |
| 마무리 | 앞선 근거로 설명할 수 있는 채용 가치 3개 내외와 간결한 연락 링크 |

## 챕터 구성

회사가 바뀌면 해당 회사의 간지를 둔다. 회사 경험이 없는 학생은 `프로젝트 A / 연구 / 동아리·캡스톤`처럼 실제 경험 단위로 묶으며 회사 경력을 만들어 넣지 않는다. 같은 회사에 제품이 여러 개라면 간지 뒤에 제품 영역을 짧게 보여주고 현재 영역을 표시한다.

간지에는 다음이 분명해야 한다.

- 회사·기관·프로젝트 그룹 이름.
- 당시 실제 역할·직함과 기간.
- 제품·고객·업무 영역을 외부인이 이해할 수 있는 한 문장.
- 해당 챕터에서 입증할 핵심 성과 3~4개를 선별한 목록. 실제 자료가 적으면 1~2개만 사용한다.

성과 상세는 [프로젝트 한 페이지 지침](project-onepager.md)의 `회사·프로젝트 계층 + 명사형 결론 + 역할·기간 + 큰 실제 근거 + 문제·내 역할 / 해결·판단 / 성과·조건 + 출처`를 기본으로 한다. 실제 이미지의 비율·가독성에 맞춰 좌/우/가운데 배치를 선택한다. 문제·선택·실패·한계는 그 프로젝트를 이해하는 데 필요한 만큼 포함한다. 성과마다 모든 단계를 별도 페이지로 늘리지 않는다. 의미가 다른 프로젝트를 한 장에 몰아넣지도 않는다.

예시 실루엣:

1. 큰 Before/After와 선택한 변경점.
2. 화면·산출물 하나와 본인 담당 범위·결과.
3. 결과 그래프와 지표 정의·조건.
4. 업무 흐름·구조도와 본인 의사결정.

수치는 결과의 의미를 설명하는 도구다. 실측이 없으면 확인한 산출물·운영 범위로 설명하고 성과 숫자를 꾸미지 않는다. `매출·전환율`, `시험·오류율`, `출시·운영` 등의 서로 다른 성과를 직무에 맞게 선택한다.

## 분량 결정

제출 조건을 우선한다. 기본 템플릿은 3개 챕터에 각 3개 성과를 둔 **18쪽 작성 예시**다. 모든 사람이 세 회사·아홉 성과를 채워야 하는 것이 아니다. 없는 챕터·성과·수상·자격은 삭제하고, 근거가 많으면 챕터별 분량을 달리한다. 한 개 프로젝트만 있거나 짧은 제출을 요구하면 그 경험의 문제·역할·판단·결과 중심으로 축약한다.

여러 회사의 경력이 있는 지원자를 8~10쪽에 강제로 압축하지 않는다. 자동 검사 기본 한도는 30쪽이며, 이는 최대 허용 검사값일 뿐 분량 목표가 아니다. 제출 한도가 따로 있으면 `check_pdf.py --kind portfolio --max-pages N`으로 해당 값을 검사한다.

## 제작·리뷰 인수조건

- Summary의 성과가 실제 상세 챕터와 정본 근거로 연결됨.
- 회사·프로젝트가 바뀌는 지점, 역할·기간이 명확함.
- 챕터의 성과 목록과 상세 페이지의 결론·수치·담당 범위가 일치함.
- 주요 근거가 읽을 수 있는 크기로 보이며 추상적 설명이나 텍스트 카드만으로 대체되지 않음.
- 수상·학력·역량은 자료가 있을 때만 포함하고 마지막은 단순 연락처가 아닌 근거 있는 채용 가치로 마무리.
- 모든 언어에서 같은 챕터 구조·사실·기여·상태를 유지하며 실제 채용 JD에 맞는 사례 우선순위를 적용.

기존 개인 포트폴리오가 제공됐다면 이 구조와 함께 그 파일을 먼저 검토하고 사용자 선호를 반영한다. 공용 템플릿에는 다른 사람의 이름·사진·회사 실적·스크린샷을 복사하지 않는다.
