# 프로젝트 한 페이지: 명사형 제목과 가변 이미지 배치

회사·프로젝트 챕터 안에서 **각 프로젝트의 대표 설명을 한 페이지**로 정리한다. 읽는 순서는 `회사/경험 그룹 → 프로젝트 → 내 문제·역할 → 해결·판단 → 성과·조건`이다. 이미지가 항상 왼쪽에 있어야 하는 것은 아니다. 실제 근거가 가장 잘 읽히는 배치를 선택한다.

## 제목과 문장

프로젝트의 고유 이름과 해당 페이지의 결론을 구분한다. 제목은 **검증된 성과를 먼저 보여주는 명사형**으로 작성한다. 우선순위는 `확인된 결과·변화 → 완성·적용한 산출물 → 직접 수행한 행동`이다. 수치가 있으면 핵심 지표와 변화량을 앞세우고, 수치가 없으면 실제 완료·적용·확인한 변화를 드러낸다. `설계`, `구축`, `개선`, `통합`, `자동화`, `단축`, `검증`, `운영 체계` 등의 명사형으로 마무리한다. 목표·진행 중인 작업은 그 상태를 보존하고 완료 성과로 바꾸지 않는다.

| 피할 제목 | 사용할 수 있는 형태, 실제 근거가 있을 때 |
|---|---|
| 고객 문의를 줄였습니다 | 문의 분류와 처리 흐름 표준화 |
| 운영 효율을 높이기 위한 | 운영 상태 요약과 검색 구조 개선 |
| 제가 만든 프로젝트 | 센서 입력과 경로 추종 모듈 구현 |
| 데이터를 활용한 혁신 | 운영 기록 분석과 우선순위 기준 수립 |

성과 중심 제목의 형식 예시: `반복 검증 시간 [실측값]% 단축`, `첫 응답 시간 [기존값]에서 [실측값]으로 단축`, `수작업 분류의 자동화와 처리 절차 표준화`. 대괄호는 실제 근거로 교체할 입력값이며 가짜 숫자로 채우지 않는다. 제목의 변화량을 설명할 기준값·측정 기간·조건은 본문/출처에 남긴다.

팀 전체 성과에 기여한 경우 소유권 수준을 정확히 표시한다. 직접 책임지지 않은 매출·전환·품질 개선을 개인 단독 달성으로 표현하지 않는다. 모델·도구 이름 자체를 성과처럼 제목으로 내세우기보다 그것으로 무엇을 바꾸고 확인했는지 먼저 쓴다. 연구·탐색·진행 중 작업처럼 성과 미측정이면 검증된 산출물이나 정확한 목표·검증 계획으로 제목을 제한한다.

`~으로`, `~위한`, `~하는`으로 끝나는 미완성 제목, 긴 문장형 제목, 근거 없는 `혁신·최적·완벽`을 피한다. 수치가 있으면 조건·출처를 확인하고, 제목을 자극적으로 만들기 위해 숫자를 추가하지 않는다. 영문은 한국어 어순을 직역하지 않고 짧은 action/result heading으로 자연스럽게 작성한다.

## 한 페이지에 남길 내용

- **상단:** 회사·프로젝트 계층, 명사형 결론, 당시 역할과 기간.
- **주요 근거:** 실제 화면·설계·Before/After·흐름·그래프 중 가장 적합한 것. 이미지에는 무엇을 입증하는지 짧은 캡션.
- **문제·내 역할:** 어떤 상황에서 무엇을 책임졌는지. 팀 전체 문제와 본인 담당 범위를 구분.
- **해결·판단:** 직접 고른 방법·대안·구현·조율·운영 변화 중 핵심 행동.
- **성과·조건:** 확인한 변화 또는 산출물, 지표·단위·측정 기간·검증 조건. 수치가 없으면 실제 완료 범위를 설명.
- **보조:** 짧은 출처·링크·필요한 한계. 자세한 근거표는 개인 QA 기록에 둠.

각 설명 블록은 보통 1~2개의 짧은 문장이나 불릿으로 시작한다. 한 페이지에 프로젝트 전체 일지를 넣지 않는다. 넘치면 중복·부차 정보를 먼저 줄이고 실제 근거 크기를 유지한다. 상세 자료가 독립적으로 필요하면 대표 한 페이지를 유지한 채 명확히 표시한 부록/추가 근거로 분리한다. 무조건 글자를 줄이거나 이미지의 중요한 부분을 잘라 한 장에 맞추지 않는다.

## 이미지 위치를 고르는 기준

배치 전에 원본의 **비율·해상도·중요한 글자·보여줄 상태·크롭 가능 여부**를 확인한다. 아래 비율은 시작점이며 실제 렌더링의 가독성이 최종 기준이다.

| 배치 | 적합한 경우 | 구성 |
|---|---|---|
| 왼쪽 이미지 | 보통 가로형 화면·산출물을 먼저 보고 오른쪽에서 해석해야 할 때 | 근거 약 55~65%, 문제·해결·성과 약 35~45% |
| 오른쪽 이미지 | 세로형 화면·사진·설계물 또는 먼저 설명을 읽는 편이 자연스러울 때 | 왼쪽 세 블록, 오른쪽 원본 비율의 근거 |
| 가운데·전체 너비 | 아주 넓은 흐름도·타임라인·가로 비교·작은 글자가 많은 근거가 전체 너비를 필요로 할 때 | 상단 제목, 가운데 큰 근거, 아래 짧은 문제·해결·성과 |

정사각·세로·일반 가로 이미지와 아주 넓은 이미지를 같은 틀에 강제로 넣지 않는다. 아주 넓은 자료라도 가운데 배치에서 실제 화면이 더 작아지면 좌우 배치와 비교해 더 읽히는 쪽을 고른다. 이미지 위치를 바꾸기 위해 **이미지 자체를 좌우 반전하지 않는다.** 같은 프로젝트의 Before/After는 비교 가능한 크기·조건으로 유지한다.

`object-fit: contain`을 화면·문서·그래프·흐름도의 기본으로 한다. 사진은 승인된 의도적 크롭만 허용하고, 잘라낸 영역이 증거를 바꾸지 않는지 확인한다. 양쪽 배치를 번갈아 쓰는 것 자체가 목적이 아니며 적합하면 같은 배치를 반복할 수 있다. 생성 이미지·가짜 대시보드로 실제 증거를 대신하지 않는다.

## 제작·리뷰 인수조건

1. 회사/경험 그룹·프로젝트·역할·기간을 혼동하지 않고 파악 가능.
2. 한국어 제목이 실제 결론의 명사형이며, 짧게 읽히고 완료/목표 상태가 정확함.
3. 대표 페이지 안에 문제·본인 역할, 해결·판단, 성과·조건이 모두 있고 정본 근거와 일치.
4. 원본 이미지의 비율·해상도에 맞는 좌/우/가운데 배치를 선택하고 이유를 간단히 기록.
5. 이미지의 핵심 글자·축·단위·상태가 실제 PDF 배율에서 읽히며 늘어짐·중요 부분 잘림 없음.
6. 문구·이미지·푸터가 충돌하지 않고 다른 언어에서도 재출력·시각 검수 완료.

피드백은 `페이지·요소 / 제목·내용·배치 문제 / 정보 전달 영향 / 실제 수정 / 재확인 결과`로 남긴다. 보기 좋은 배치가 사실·기여·지표 조건을 대체하지 않는다.
