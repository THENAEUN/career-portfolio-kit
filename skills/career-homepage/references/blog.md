# Markdown 블로그 규약

## 파일과 frontmatter

`content/blog/<slug>.md`가 정본이다. 제목·날짜·본문은 필수이며 요약은 목록·SEO에 사용한다. 파일명에서 slug를 얻어 메타데이터와 경로가 어긋나지 않게 한다. 소문자 영문·숫자·하이픈 slug를 기본으로 하며 `page`처럼 라우트와 충돌하는 값은 거절한다. 중복 slug는 빌드 오류로 표시한다.

```yaml
---
title: "사용자가 확인한 실제 글 제목"
date: "2026-11-21"
description: "목록과 검색에 표시할 짧은 요약"
author: "공개할 작성자명"
category: "프로젝트 회고"
tags: ["제품", "회고"]
draft: true
# thumbnail: "/images/blog/my-first-post/cover.webp"
# updated: "2026-11-22"
---
```

- `date`는 발행일, `updated`는 선택 수정일이다. 따옴표로 감싼 유효한 `YYYY-MM-DD` 문자열로 검증하고 `updated >= date`를 확인한다. 형식만 같은 불가능한 날짜도 거절한다.
- `draft`는 필수 boolean이다. 누락/문자열을 임의로 false로 바꾸지 않는다. 누락 메타데이터·빈 제목/본문·유효하지 않은 이미지는 파일과 원인을 명시한 빌드 오류로 보여준다.
- `draft: false`이고 발행일이 사이트 기준 오늘 이전/당일인 글만 공개한다. 기본 시간대는 한국어 개인 사이트의 `Asia/Seoul`이며 사용자 지역이 다르면 설정한다. 날짜를 UTC 자정으로 파싱해 표기일이 하루 달라지지 않게 한다.
- 정적 배포에서 예약일이 돼도 재빌드 전에는 자동 발행되지 않는다. 기본 운영은 직접 배포이며 예약 자동화를 약속하지 않는다. 자동 예약이 필요할 때만 별도 재빌드 방식과 서비스 한도를 검토한다.
- 공개 글을 `date DESC, slug ASC`로 안정 정렬한다. 목록·상세·페이지 데이터·메타데이터·관련 글·sitemap 모두 같은 공개 필터를 사용한다. 초안의 URL 직접 접근은 404이며 원본 Markdown과 초안 본문을 public/ 또는 클라이언트 번들에 복사하지 않는다.
- 작성자·공개 여부가 미확정이면 `draft: true`로 유지한다. 템플릿 날짜·제목을 실제 사실로 오인하지 않도록 첫 작성에서 교체한다.

`posts.ts`는 `server-only`로 fs/파서/공개 필터를 캡슐화한다. 사용자 URL을 그대로 fs 경로에 붙이지 않고 검증된 글 목록의 slug로 조회한다. 브라우저에는 목록용 공개 메타데이터와 해당 페이지 데이터만 전달한다.

## 본문과 이미지

`.md`를 `react-markdown` + `remark-gfm`으로 렌더링하고 제목·문단·목록·표·인용·코드·링크·이미지에 공통 스타일을 적용한다. raw HTML은 기본 허용하지 않는다. `rehype-raw`와 `dangerouslySetInnerHTML`을 단순 편의를 위해 추가하지 않는다. 링크/이미지 URL은 http(s) 또는 허용된 로컬 경로만 사용하고 위험한 프로토콜을 거절한다.

이미지는 직접 제공하거나 공개 권한을 확인한 자산만 사용한다. `public/images/blog/<slug>/screen.webp` 파일은 본문에서 다음처럼 참조한다.

```md
## 선택한 방법

실제 자료를 바탕으로 판단 이유를 설명합니다.

![변경한 화면에서 확인할 핵심 내용](/images/blog/my-first-post/screen.webp)

*그림 1. 화면의 의미와 필요한 출처 설명.*

다음 문단에서 결과와 한계를 이어서 설명합니다.
```

이미지 삽입은 선택이며 이미지가 없으면 해당 줄 자체를 넣지 않는다. Git에 실제 파일이 있는지 빌드 전에 확인한다. 경로의 대소문자가 Linux 배포에서도 일치해야 한다. 카드 썸네일이 없으면 일관된 텍스트형 레이아웃으로 처리하고 깨진 그림을 만들지 않는다. 꾸밈용 기본 썸네일을 실제 프로젝트 화면처럼 표시하지 않는다.

Next Image를 쓰면 실제 width/height를 수집해 레이아웃 이동을 줄인다. 일반 img를 쓰는 경우에도 크기/비율과 반응형 스타일을 제공한다. 본문 이미지는 적절히 지연 로드하고, 대표 이미지는 실제 화면과 성능을 보며 판단한다. 큰 원본은 웹용으로 줄이고 alt와 출처를 보존한다. 외부 이미지는 허용 호스트와 영속성을 확인하고, 비공개 Notion 임시 이미지 URL을 영구 자산처럼 쓰지 않는다.

## 페이지네이션을 바탕으로 한 무한스크롤

권장 페이지 크기는 9개이며 설정 한 곳에서 바꿀 수 있게 한다. 1개 글만 있으면 다음 페이지·더 보기·observer가 작동하지 않아야 한다.

1. `/blog`는 1페이지 글을 초기 서버 HTML로 렌더링한다. `/blog/page/2`부터도 해당 묶음의 글을 서버 HTML로 직접 제공한다. `/blog/page/1`은 `/blog`로 리디렉션한다.
2. 서버가 동일한 정렬·페이지 크기로 **페이지별 JSON 파일**을 빌드 시 생성한다(예: `public/blog-pages/2.json`). 여기에는 공개 목록 메타데이터만 넣는다. 생성 전 해당 생성물 전용 폴더의 지난 결과를 정리해 초안 전환/삭제 글이 오래된 JSON에 남지 않게 한다. 페이지 데이터 생성과 build 순서를 package.json에 연결한다. 대안은 동일 필터를 적용한 페이지별 Route Handler이며 프로젝트 방식에 맞게 하나를 선택한다.
3. 클라이언트 `archive-feed`는 하단 sentinel에 `IntersectionObserver`를 붙여 다음 묶음만 요청하고 추가한다. 전체 글 데이터와 본문을 첫 화면에서 전부 내려보내 숨기는 구현으로 대신하지 않는다.
4. `isLoading`, `hasNext`, 페이지 번호, 요청 실패·재시도 상태를 관리한다. 동일 페이지 동시 요청과 중복 slug를 막고 끝에 도달하면 observer를 해제한다. unmount/필터 변경 시 이전 요청을 취소하거나 무시한다. 실패 시 페이지를 건너뛰지 않는다.
5. 항상 탐색 가능한 `<a href="/blog/page/2">다음 페이지</a>`와 이전 페이지 링크를 서버 HTML에 유지한다. 자동 로딩과 별도로 수동 “더 보기/다시 시도” 버튼을 제공한다. 키보드·JS 비활성·IntersectionObserver 미지원에서도 다음 글을 읽을 수 있어야 한다. 페이지 번호를 fragment(`#page-2`)로만 관리하지 않는다.
6. 직접 진입한 `/blog/page/2`는 2페이지 글부터 보여주고 뒤의 묶음을 추가 로드한다. 글을 눌렀다 뒤로 돌아올 때는 해당 목록 URL·로드 범위·스크롤 위치를 복원한다. 구현이 단순한 초기 버전은 목록 복귀용 페이지 링크를 함께 제공하고 실제 뒤로가기 복원을 검증한다.
7. 무제한 자동 로딩 때문에 푸터를 영원히 못 누르지 않도록 연속 자동 로드 횟수에 상한(예: 3회)을 두고 이후는 “더 보기”로 전환한다. 사용자가 직접 활성화한 버튼의 포커스를 유지한다. 공개 글 0개/마지막 묶음은 각각 빈 상태/마지막 안내를 보여준다.

Google은 버튼 클릭이나 사용자 스크롤을 자동으로 수행하지 않으므로 페이지 URL과 실제 링크를 유지한다. 각 목록 페이지는 자체 canonical을 가진다. [Google 페이지네이션·증분 로딩 지침](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)을 참고한다.

## 첫 글과 이후 운영

첫 글 대화는 주제 → 독자/전하고 싶은 점 → 사실·이미지 확인 → `.md` 초안 → 사이트 미리보기 → 요청된 범위에서 발행 순서로 진행한다. 기술직이 아니면 기술 회고를 강요하지 않고 기획·운영·디자인·분석 사례도 허용한다. 없는 경험은 채우지 않는다.

사용자에게 짧은 운영법을 남긴다: `content/blog/새-주소.md` 추가 → 제목·날짜·요약·본문 작성 → 선택 이미지 복사/삽입 → 미리보기 → 발행할 때 `draft: false` → Git 반영 → Vercel 재배포. 파일/이미지 삭제와 초안 전환도 새 빌드가 필요하다. 글 하나를 더 추가해도 FE 템플릿을 수정할 필요가 없어야 한다.
