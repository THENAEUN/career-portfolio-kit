# 커리어 포트폴리오 PPT 10장 설계표

이 문서는 수업 발표나 단일 사례를 깊게 설명하는 대안 구성이다. 채용 포트폴리오의 기본은 [회사·프로젝트별 챕터](../skills/html-pdf-portfolio/references/chapter-structure.md)와 [프로젝트 대표 한 페이지](../skills/html-pdf-portfolio/references/project-onepager.md)다. 한 프로젝트의 문제·해결·성과를 기본 한 페이지에 담고, 깊이 있는 설명이 별도로 필요할 때 아래 설계표를 선택한다.

이 문서는 PowerPoint에 옮길 내용 설계표다. 프로젝트 2건 중 대표 사례에 6장, 보조 사례에 1장을 배정한다. 프로젝트가 하나뿐이면 보조 사례를 지어내지 말고 현재 보유 경험을 표시한 뒤 멘토와 구성을 조정한다.

첫 취업·이직·경력 전환에 사용할 수 있다. 아래 기술·실험 예시는 해당할 때 적용하고 비개발 직무는 업무 구조·정책·디자인·캠페인·운영·사업 산출물로 바꾼다. 10장은 구성 예시이며 사용자·제출 조건을 우선한다.

| 장 | 답할 질문 | 넣을 내용 | 추천 시각 자료·근거 |
|---:|---|---|---|
| 1 | 어떤 역량을 가진 지원자인가? | 이름·희망 직무·근거 있는 역량 한 문장 | 대표 경험 이미지, 관련 근거 링크 |
| 2 | 어떤 경험이 이를 뒷받침하는가? | 프로젝트 2건의 문제·역할·검증 상태·기간 | 두 사례 비교표 |
| 3 | 대표 프로젝트는 무슨 문제를 푸는가? | 사용 환경·문제·성공 기준·범위 | 현장 또는 시뮬레이션 화면과 설명 |
| 4 | 시스템은 어떻게 동작하는가? | 입력·처리·출력·모듈, 내가 맡은 부분 | 구조도에 담당 모듈 표시 |
| 5 | 본인이 어떤 판단과 구현을 했는가? | 선택 이유·대안·직접 바꾼 코드 | 짧은 코드 또는 설계 전후 비교와 파일 링크 |
| 6 | 결과는 어떻게 검증했는가? | 기준 방법·변경 방법·조건·반복·지표 | 축과 단위가 있는 그래프·결과 표·로그 링크 |
| 7 | 실패를 어떻게 해석하고 수정했는가? | 실패 조건·가설·수정·미해결 한계 | 실패 장면과 원인·수정 설명 |
| 8 | 이 결과는 어디에 활용할 수 있는가? | 적용 가능 업무·기술적 의미·미검증 영역 | 기술 지표와 활용 상황의 연결 그림 |
| 9 | 보조 프로젝트는 어떤 역량을 더 보여주는가? | 다른 문제·기여·결과·링크, 중복 설명 축소 | 실제 산출물 1개와 역할 설명 |
| 10 | 다음에는 무엇을 검증할 것인가? | 핵심 역량·다음 실험·저장소·블로그 링크 | 핵심 근거 3개와 클릭 가능한 링크 |

## README와 PPT에서 같은 근거 쓰기

| 근거 | README | PPT |
|---|---|---|
| 프로젝트 조건·목표 | 문제와 목표 | 3장 |
| 입력·처리·출력 | 시스템과 기술 선택 | 4장 |
| 본인 수정 코드 | 나의 기여 | 5장 |
| 설정·원자료·그래프 | 실험과 결과 | 6장 |
| 실패와 한계 | 실패·수정·한계 | 7장 |
| 적용 가능성 | 활용 가능성 | 8장 |

## 장별 작성 규칙

- 제목은 검증된 성과·변화를 먼저 보여주는 명사형 결론으로 쓴다. 결론을 낼 근거가 없으면 정확한 목표·산출물·검증 계획과 상태를 표시하며 미측정 성과를 만들지 않는다.
- 한 장에는 중심 주장 하나와 그 주장을 뒷받침하는 시각 자료 하나를 둔다.
- 그래프는 축·단위·조건을, 영상 캡처는 상황·시점을 설명한다.
- 시뮬레이션·실기·목표·실측·미검증을 보이는 곳에 표시한다.
- 16:9를 기본으로 하고 한글 글꼴·본문 크기·출처 위치를 통일한다. Pretendard를 사용할 경우 제출 환경에서의 표시도 확인한다.
- QR코드만 두지 말고 클릭 가능한 텍스트 링크를 함께 둔다.
- 최종 확인은 슬라이드를 실제로 열어 수행한다. PDF 제출도 가능하면 내보낸 PDF를 별도로 확인한다.

## AI에 그대로 전달할 요청

```text
첨부한 프로젝트 코드, 실험 로그, 기존 문서만 근거로 이 10장 설계표를 채워 주세요.
먼저 확인한 사실, 부족한 증거, 추가 질문을 구분해 주세요.
지원자 본인의 기여와 팀·협력사·오픈소스·AI의 기여를 분리해 주세요.
수치가 없으면 미측정으로 두고 가장 작은 추가 검증을 제안해 주세요.
각 장에 제목, 핵심 주장, 시각 자료 요청, 출처, 발표 메모를 작성해 주세요.
README와 수치·역할·검증 환경이 일치하는지도 확인해 주세요.
```
